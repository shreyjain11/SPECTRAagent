# Inline analysis notebooks

Open the [notebook index](INDEX.md), [local browser index](index.html), or [machine-readable index](index.json). Each available entry links its executed notebook, rendered results, and a hash-bound execution record. The six sections contain acquisition, processing, axis and level construction, model evaluation or released scores, curves and controls, and the calculated decision with its explanation.

All custom calculation code is in notebook cells. Run All recalculates derived data and results. Verified public downloads may be reused; model predictions may be reused only where the notebook explicitly verifies their input, checkpoint and setting identity. A candidate without outcome measurements has an explicit stopping diagnostic, not an invented curve. Entries awaiting execution remain marked as pending.

For example, from the repository root:

```sh
python3.11 -m venv .venv-state
.venv-state/bin/python -m pip install -r reproduction/inline/state/requirements-codex.txt
.venv-state/bin/python reproduction/run_notebooks.py \
  --analysis state-codex-r1/test-01 --python .venv-state/bin/python
```

Alternatively, install the relevant packages in a Jupyter kernel, open a notebook, and Run All from its directory. Small adjacent `inputs/` manifests are included where needed. Raw datasets, model weights, compiled tools and generated caches are acquired by the displayed cells and are not Git assets. Raw-data and model stages can be large or long-running; their actual scope is shown before execution.

The runner writes a separate executed copy and log under `reproduction/.executions/`. `--model-python MODEL=PYTHON` selects interpreters for mixed groups. Preferred execution refuses pending entries; it never silently selects another analysis implementation. `--implementation supporting` and `--implementation public-bundle` explicitly select the separate supporting routes.

## Reading results

Section 6 of each notebook is the current result. Its explanation follows the displayed calculations and controls. The registry's supporting summaries are not substituted for these results. A successful execution means that the visible workflow completed without cell errors; it does not imply a positive scientific finding or equivalence to another software version or data population.

Execution records bind the exact notebook and rendered HTML, count executed cells, list the six section locations and point to the result cells. Included input manifests and calculation receipts are fingerprinted. They are provenance and review evidence; calculated outputs are generated by the notebook code.
